# AI-Generated Web Dashboard Design

## Goal

Create a one-time, AI-generated HTML dashboard for Home Assistant that is served from the existing `www/` folder and requires no YAML. The AI chooses which entities to display and how to lay them out based on the live entity registry; the generated page then connects back to Home Assistant over the WebSocket API for live state updates and control.

## Constraints

- No YAML configuration in Home Assistant.
- No new custom integration or add-on.
- One self-contained generated HTML/CSS/JS file.
- Served by Home Assistant from `www/ai-dashboard/index.html`.
- AI decides initial layout and entity selection from the entity registry.
- Live updates and service calls use the Home Assistant WebSocket API.
- LLM access via an OpenAI-compatible chat completions endpoint using a token stored outside the generated file.

## Architecture

```
┌─────────────────────────────────────────────────────────────┐
│  scripts/generate_ai_dashboard.py                           │
│  - reads HA_URL + token (env / secrets.yaml / prompt)       │
│  - fetches entity registry + states from HA REST API        │
│  - builds compact entity summary                            │
│  - sends structured prompt to LLM                           │
│  - parses returned HTML/JS                                  │
│  - writes www/ai-dashboard/index.html (+ backup)            │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│  Browser loads https://<ha>/local/ai-dashboard/index.html   │
│  - prompts user for long-lived access token                 │
│  - opens HA WebSocket connection                            │
│  - subscribes to state_changed events                       │
│  - renders cards/sections generated by the LLM              │
│  - sends service calls on user interaction                  │
└─────────────────────────────────────────────────────────────┘
```

## Components

### 1. Generator script: `scripts/generate_ai_dashboard.py`

- **Configuration input**: `HA_URL`, `HA_TOKEN`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Read from environment variables or an optional `.env` file. The API key is never written into the generated HTML.
- **Entity fetch**: Calls `/api/config/entity_registry/list` and `/api/states`. Filters out `unavailable`/`unknown` entities, excludes diagnostic/noisy domains (`update`, `device_tracker` if not wanted, etc.), and groups by domain.
- **Prompt construction**: Builds a compact JSON/CSV summary of entities (entity_id, friendly_name, state, domain) and appends design instructions:
  - dark theme, responsive grid, large touch targets suitable for wall panels;
  - group related entities (lights, climate, sensors, media, printers, etc.);
  - generate a single HTML file with embedded CSS and vanilla JS;
  - use the Home Assistant WebSocket API at `/api/websocket`;
  - read the access token from `window.prompt()` / `localStorage`;
  - support toggling lights/switches and showing sensor values.
- **LLM call**: Sends the prompt to the configured OpenAI-compatible endpoint with a request for structured output (HTML block only).
- **Output parsing**: Extracts the HTML from the response (markdown code fence or raw HTML). Validates that it contains the required WebSocket boilerplate; if not, injects a safe fallback connection wrapper.
- **File output**: Writes to `www/ai-dashboard/index.html`, creates `www/ai-dashboard/index.html.bak.<timestamp>` before overwriting.

### 2. Generated dashboard: `www/ai-dashboard/index.html`

- **Self-contained**: All CSS and JS embedded in one file; no external dependencies.
- **Authentication**: On first load, prompts for a Home Assistant long-lived access token and stores it in `localStorage`. A "Logout / Change token" button clears it.
- **Connection**: Opens `wss://<ha>/api/websocket`, authenticates with the token, subscribes to `state_changed`, and maintains a reconnect loop.
- **Rendering**: Updates the DOM when state changes arrive. Cards use `data-entity-id` attributes so the generic state handler can map updates.
- **Controls**: Light/switch cards call `call_service` (`homeassistant.toggle` or domain-specific `turn_on`/`turn_off`).
- **Status bar**: Shows connection state (connecting / connected / disconnected).

### 3. Optional helper: `scripts/create_ha_token.md`

- Short markdown note explaining how to create a long-lived access token in Home Assistant's user profile.

## Data flow

1. User runs `python3 scripts/generate_ai_dashboard.py`.
2. Script fetches entity registry and states from HA REST API.
3. Script sends a structured prompt to the configured LLM.
4. LLM returns a single HTML file string.
5. Script parses, validates, and writes it to `www/ai-dashboard/index.html`.
6. User navigates to `https://<ha>/local/ai-dashboard/index.html`.
7. Browser prompts for token, connects to `/api/websocket`, and renders live data.
8. State changes pushed by HA update the dashboard in real time.
9. User taps a light card → browser sends `call_service` over WebSocket → HA toggles the light.

## Security

- The access token is never hard-coded in the generated HTML or committed to git.
- The token is supplied by the user at page load and kept in browser `localStorage`.
- The generated page is served from the same origin as Home Assistant (`/local/`), so it can reach `/api/websocket` without CORS issues.
- The script's API key is read from environment variables, not from `secrets.yaml` (which Home Assistant owns), to keep the generator independent.
- The script filters out sensitive domains/entities (camera streams, alarm panels, locks) by default; the user can adjust the filter.

## Error handling

- If the LLM response cannot be parsed as HTML, the script logs the raw response and falls back to a minimal but working dashboard template.
- If HA is unreachable or the token is invalid, the script prints a clear error and exits without overwriting the previous dashboard.
- The generated page shows connection status and attempts automatic reconnection with exponential backoff.
- Missing or renamed entities render as "entity not found" instead of crashing the page.

## Verification

1. Run the generator with a valid HA token and LLM key.
2. Confirm `www/ai-dashboard/index.html` is created and contains valid HTML.
3. Open `https://<ha>/local/ai-dashboard/index.html` in a browser.
4. Enter a long-lived access token and confirm "connected" status.
5. Verify live state updates appear for at least one sensor and one light.
6. Tap a light/switch card and confirm the corresponding HA entity toggles.
7. Re-run the generator and confirm a timestamped backup is created.

## Out of scope

- Natural-language re-editing from the browser (no chat UI in v1).
- Multi-user authentication or per-user layouts.
- Hosting outside Home Assistant or over the public internet.
- Camera live streams (still images/urls may appear, but no video pipeline).
- Integration with Home Assistant's native Lovelace dashboard system.
